# ADR 0001 — Data and persistence conventions

**Status:** Accepted · **Issue:** [#27](https://github.com/imonroe/brawling-mahogany/issues/27) · **Sources:** PRD §7.14, §8.1, §9 · IA §6, §12

## Context

Forty-odd tables are coming. Every convention below is cheap to set before the
first migration and expensive to retrofit afterwards — a key type, a delete
strategy, or a money representation changed at table thirty means touching
twenty-nine migrations, their models, their factories, and every URL that
carries an identifier.

This ADR is deliberately written before any business table exists.

## Decision

### Identifiers: ULIDs, everywhere a person can see them

Primary keys are ULIDs (`char(26)`), not sequential integers.

A sequential identifier in a URL leaks two things at once: how many deals a
team has, and how many the product has. It also makes an enumeration attack
trivial in a product whose tenant boundary is the whole security model. ULIDs
sort by creation time, which keeps index locality reasonable, and they are
generated by the application, which means a record can be created and
referenced in the same request without a round trip.

Encoded by `App\Models\Concerns\HasProductDefaults` (Laravel's `HasUlids` plus
`SoftDeletes`) and `$table->productDefaults()`.

`users` — the precursor to `people` — was migrated to a ULID key and soft
deletes as part of this decision rather than left as the one table with a
sequential id. The convention having an exception on day one is how conventions
stop being conventions.

**Slice 1 completed that sentence:** `users` *is* `people` now, one row per
human with credentials optional (PRD §6.2 F2.1). See the decision log entry
dated 2026-08-22.

### Timestamps and soft deletes on every business table

`created_at`, `updated_at`, and `deleted_at`, always.

PRD §9 sets deletion policy: soft delete with a **30-day recovery window, then
a hard delete**, and team deletion purging within 30 days. A table without
`deleted_at` cannot honour that policy, and a model without `SoftDeletes`
silently makes deletion irreversible.

**The scheduled purge job is not in this slice.** It belongs with the first
records worth purging — file it in Slice 1 alongside team deletion. Soft delete
without a purge is a data-retention problem waiting to be discovered by a
customer's lawyer, so it does not get to wait longer than that.

### `team_id` on every business table

Not nullable, not optional, and indexed. The enforcement layers are
[ADR 0002](0002-multi-tenancy-enforcement.md); this ADR fixes the column.

`$table->productDefaults(teamScoped: false)` exists for the deliberate
exceptions. Every exception is recorded in
`tests/Isolation/ModelTenancyConventionTest.php`, which fails when a new model
is neither scoped nor listed, and there are six: `people` (shared across
teams — PRD's 2026-08-22 decision), `teams` itself, `roles` (the five system
roles have no team), `permissions` (flat and identical everywhere),
`audit_log` (which outlives the team it describes), and `passkeys` (a
credential belongs to a human, not a tenancy).

**Slice 1 flipped `$constrained` to default true**, as this ADR said it would
once `teams` existed. `productDefaults()` now also adds a unique index over
`(team_id, id)` — not because `id` needs one, but because Postgres will only
accept a composite foreign key if the parent carries it. That is what makes
`$table->teamScopedForeign('stage_id', 'stages')` possible, and with it ADR
0002's second enforcement layer: a child row pointing at a parent in another
team is a database error rather than a code review.

### Table names match the PRD §6.2 entity reference exactly

`deals`, `stages`, `gates`, `tasks`, `key_dates`, `activity_events`. The
superseded names — `projects`, `project_participants`, `milestones` in the old
broad sense, `client_portal` — must never appear in a migration.
`tests/Unit/CodeDisciplineTest.php` fails the build when one does.

`stages.is_milestone` and `stages.milestone_label` are the *new*, narrower
meaning of milestone (IA §3) and are correct.

### Time: UTC in storage, team timezone in display

Every timestamp is stored in UTC. `teams.timezone` drives display, and the
frontend formats through `resources/js/lib/formatters.ts` rather than in
components (IA §10).

Dates that are genuinely dates — an inspection deadline is a calendar day, not
an instant — are stored as `date`, not `timestamp`. A contingency deadline that
shifts because a server is in a different timezone is a legal problem, not a
formatting one.

### Money: integer cents, never a float

`$table->money('transaction_value')` is a `bigint`. Binary floating point is
not an acceptable way to hold somebody's house price, and `numeric` invites
implicit casts to float somewhere downstream. Formatting is
`formatCurrency()`'s job (IA §10: whole dollars above $1,000).

### Configuration columns: JSONB

`config`, `payload`, `settings`, `contingencies`, `template_snapshot`. Postgres
was chosen partly for this (PRD §8.1): JSONB can be indexed and constrained,
JSON text can be neither.

`$table->config('settings')` is the macro.

### States: PHP enums, values matching IA §8 exactly

Every state lives in `app/Enums/` as a string-backed enum whose values are
`snake_case` and whose labels are Title Case.
`tests/Unit/DocumentedVocabularyTest.php` reads Information Architecture §8 and
PRD §6.3 and fails when the code and the documents diverge.

Enum-backed columns are `string` with an application-level cast, plus a check
constraint where the value set is genuinely closed. The UI label mapping lives
in `resources/js/lib/states.ts`, never in the enum value.

### Encryption at rest for credentials and tokens

PRD §9 requires application-level encryption for stored credentials and tokens.
Every column holding a provider key, an iCal feed token, a webhook secret, or a
two-factor secret uses Laravel's `encrypted` cast. Two consequences worth
stating plainly:

- An encrypted column cannot be queried by value. Anything that needs lookup
  (a magic-link token, an iCal feed token) stores a **hash** for lookup and the
  encrypted value only if the plaintext is genuinely needed later.
- Rotating `APP_KEY` re-encrypts nothing on its own. The rotation procedure is
  in `docs/Environment and secrets.md`.

## Consequences

- `$table->productDefaults()` is one line at the top of every business
  migration, and the defaults are impossible to forget by accident.
- ULID keys are 26-byte strings rather than 8-byte integers. At the scale in
  PRD §9 — 200 teams, hundreds of deals each, 500,000 activity events — the
  index cost is real but small, and the alternative leaks tenancy information
  in every URL.
- Soft deletes mean every query carries a `deleted_at is null` predicate.
  Composite indexes need to account for it.
- Integer cents mean the application, not the database, owns currency
  formatting. That is the right place for it, since display rules differ
  between the internal app and a client-facing email.

## Not decided here

- The global tenancy scope and how the current team is resolved — see
  [ADR 0002](0002-multi-tenancy-enforcement.md).
- Whether `people` is team-scoped, shared, or duplicated (IA §13). The
  convention supports either; the decision belongs with Slice 1.
- The hard-delete purge job's schedule and retention accounting.
