**Properties** is the homes your team is working on. A property exists on its
own and can be attached to any number of deals — the same house can be a
listing this year and a purchase next.

## Adding one

**Add property** takes the address, type, status, and the details you have:
beds, baths, square footage, year built, parcel number.

Parcel numbers are normalised, so the same parcel written three ways is
recognised as one property.

## Links out

A property holds **external links** — the MLS listing, the county record, a
listing site, a virtual tour. Each is a label and a URL.

**The app stores the link and never the content behind it.** Listing data is
licensed, and copying a price or a photo across would be a licensing decision
rather than a convenience. So there is no field for a price or a description
here on purpose.

Links are held to http and https addresses.

## Photographs

A property has a gallery. Upload, reorder, and set which one is the primary —
the first one becomes primary on its own, so the common case arranges itself.

Photographs are **private**. There is no public URL: every view goes through
the app, which checks that you are allowed to see it and records that you did.
Deleting one deletes the file immediately.

Images only, for now, and the app checks what a file actually is rather than
trusting its name.

> **Do not upload documents here.** Bank statements, contracts, identification
> and lending packets do not belong in a photo gallery. The proper document
> handling — with the categories and refusals that belong around sensitive
> paperwork — arrives in a later release.

## Properties on a deal

A deal's **Properties** tab shows the ones in play. One is the **subject** —
the property the deal is actually about — and it is what the deal is named
after.

On a buyer's deal, the others are candidates, each marked with where it stands:
interested, shortlisted, passed, or other. When one is accepted, promote it to subject and
the deal renames itself.
